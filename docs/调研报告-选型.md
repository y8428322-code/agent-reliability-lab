## 2. 选定 Qwen-Agent 的理由

1. **接入成本已验证**：源码 `qwen_agent/llm/oai.py` 的 `TextChatAtOAI.__init__` 直接读 `cfg.get('base_url')` 与 `cfg.get('api_key')`，无需改上游任何一行代码即可指向任意 OpenAI 兼容服务。
2. **协议兼容已实测**：MiniMax 的 OpenAI 兼容端点实测返回 `tool_calls`，这是 agent 框架能工作的前提。
3. **功能面覆盖未来魔改所需**：Function Calling（工具调用）、ReAct（多轮推理）、RAG（知识检索）、MCP（外部工具接入）、GroupChat（多 agent 编排）齐备，不必再引入第二个框架。
4. **License 干净**：Apache-2.0，允许在商用项目上改造。
5. **中文优先**：README_CN 完整，后续做业务向魔改时文档成本低。
6. **规模适中**：不是 AutoGen/AgentScope 那种需要先读万行代码才能上手的体量，适合个人项目边跑边改。

## 8. 上游踩坑记录（实测得出，魔改前必读）

复现过程中撞到 4 个上游/环境层面的问题，都已在本工程绕过，记录下来供后续魔改参考：

### 8.1 `setup.py` 漏声明依赖，`import qwen_agent` 直接失败

上游 `install_requires` 里没有 `numpy` / `soundfile` / `ipykernel` / `regex` / `tqdm`，但这些都在**模块级 import**：

| 包 | 被谁 import | 后果 |
|---|---|---|
| `numpy` | `qwen_agent/utils/utils.py` | `import qwen_agent` 即崩 |
| `soundfile` | `qwen_agent/utils/utils.py` | 同上 |
| `ipykernel` | `qwen_agent/tools/code_interpreter.py` | 同上（`tools/__init__.py` 会连带 import） |
| `regex` / `tqdm` | `qwen_agent/tools/python_executor.py` | 同上 |

**处理**：写进本工程 `requirements.txt` 并在 `scripts/setup_env.sh` 里安装。

> 另有一批更重的（`matplotlib` / `pandas` / `seaborn` / `sympy`）只在 `tools/resource/code_interpreter_init_kernel.py` 里用到，
> 属于 `code_interpreter` 工具的内核脚本，本工程未挂载该工具，因此**没有安装**。

### 8.2 `reasoning_content` 会吞掉 `tool_calls`（最危险的一个）

上游 `qwen_agent/llm/oai.py::_chat_no_stream` 的实现是：

```python
if hasattr(response.choices[0].message, 'reasoning_content'):
    return [Message(role=ASSISTANT, content=..., reasoning_content=...)]   # ← tool_calls 被丢弃
else:
    return [Message(role=ASSISTANT, content=...)]
```

MiniMax-M3.1-Flash **恒返回 `reasoning_content`**，一旦走非流式分支，模型发起的 `tool_calls` 会被静默丢掉，表现为"工具永远不触发"。

**规避**：上游 `Agent._call_llm()` 的 `stream` 参数默认就是 `True`，走 `_chat_stream` 分支，该分支**正确处理了 `tool_calls`**（会累积分片参数）。因此不要去关流式。
> 若将来要强制非流式，必须在自己的封装层**继承 `TextChatAtOAI` 并重写 `_chat_no_stream`**，把 `response.choices[0].message.tool_calls` 一并转成 `FunctionCall`。

### 8.3 流式返回是"累积式"，不是"增量式"

- assistant 的 `content` 每轮 yield 的是**当前全文**，不是新增片段；
- `function_call.arguments` 是**分片增量**（`"{"` → `'{"numbers"'` → 完整 JSON）。

**处理**：本工程 `demo.py::run_and_report` 按工具名合并分片（保留最长参数），并只保留最后一次非空内容作为最终回答。

### 8.4 `GroupChat` 的成员工具必须注册进全局 `TOOL_REGISTRY`

`GroupChat` 里成员的 `selected_tools` 只能填**工具名**，内部走 `TOOL_REGISTRY[name]` 查找；直接传 `BaseTool` 实例会抛 `ValueError: Tool xxx is not registered.`。

**处理**：本工程的工具类加了 `@register_tool(name, allow_overwrite=True)` 装饰器（上游惯例），注册后 `selected_tools: ["sum_numbers"]` 可用。
