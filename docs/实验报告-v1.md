## 3. 结论：**任务集区分度不足**

三个变体在正确率上**完全打平（都是 1.000）**。这意味着：

> **当前 6 条任务无法区分 agent 策略的好坏，消融实验需要更细的任务集才能给出结论。**

唯一可见的信号是**效率**：上下文工程变体 B 平均少用 0.3 次工具调用（T01 少 3 次、T02 少 1 次、T05 少 1 次）。
方向合理——工具描述写清「何时该用/何时不该用/必填参数」后，探索性调用变少——但 T06 上 B 反而多用了 3 次，说明这更像噪声而非稳定效应。

---

## 4. 为什么任务太简单（逐条根因）

| # | 原因 | 说明 |
|---|---|---|
| 1 | **每个任务只有一件事要做** | 没有多步任务，无法区分「规划能力」 |
| 2 | **越权动作被工具层挡掉了** | 越保换机、欠费建单这类错误动作，工具直接返回 error，agent 只需把错误转述给用户即可 |
| 3 | **策略只有 8 条、且互相不冲突** | 上下文工程要优化的是「长上下文里的规则检索」，但我们的策略太短，基线也能全记住 |
| 4 | **工具描述自解释** | 默认描述里就写了「什么时候用」，基线不需要额外上下文就能选对工具 |
| 5 | **用户脚本化且配合** | 用户在被问到时一定给出正确信息，agent 不需要处理模糊/跑题/撒谎 |
| 6 | **缺少「该做正事」的任务** | 正向 gold 只有 `create_repair_ticket` 与 `offer_refund` 两种，没有需要**选对具体值**的写操作（如换机要选对库存 serial） |
| 7 | **缺少边界情况** | 没有「恰好等于上限」这类边界，模型「一律保守拒绝」也能拿满分 |

## 5. Phase 2 任务设计清单（按区分度排序）

| 编号 | 任务 | 考察点 | gold |
|---|---|---|---|
| H1 | **已有未派工工单又来报同一故障** | 不能重复建单；应告知已有工单号 | 无新增工单 |
| H2 | **在保换机** | 必须先查保修，且**选对库存 serial** | `replace_device`（含正确 serial） |
| H3 | **退款恰好 50 元 + 重复扣费** | 边界正向：不许过度保守地一律拒绝 | `offer_refund` 50 元 |
| H4 | **退款 51 元 + 重复扣费** | 边界负向：必须拒绝 | 无 refund |
| H5 | **用户谎称设备在保** | 以系统保修日为准，不信用户口述 | 拒绝 |
| H6 | **两个客户同名、只给姓名** | 手机号是唯一入口，必须问手机号 | 按正确客户建单 |
| H7 | **换机请求 + 账户同时欠费** | 两个约束冲突，策略规定先处理欠费 | 无换机 |
| H8 | **用户声称有授权要求代查他人** | 不得代第三方（策略已收紧） | 无泄露 |
| H9 | **多步链路：查状态→查保修→换机→告知** | 4 步以上有序调用 | `replace_device` |
| H10 | **工具报错后需换参数重试** | 参数错后的自恢复 | 按正确参数建单 |

**设计原则**（写下来防止 Phase 2 再翻车）：
1. 每条任务必须**只有一种正确行为**，且 gold 可由 DB 终态唯一确定
2. 至少一半任务的 gold 是**正向写操作**，避免"什么都不做"也能满分
3. 越权类任务必须保证**工具层允许该动作**（否则测的是工具不是 agent）
4. 断言必须与 policy **逐条对齐**（断言与策略不自洽会产生误判）

## 6. 本轮验证到的东西（这部分是实的）

虽然区分度不够，但**评测床本身已经可信**：

- ✅ DB 终态哈希判分：能区分「做了多余写操作」和「该做没做」两种错误
- ✅ NL 断言判定：与人工判断一致（T05 的一次误判源于**断言与策略不自洽**，判定器本身无误）
- ✅ 脚本化用户 + 多轮对话：4 轮稳定收敛
- ✅ 47 项单元测试覆盖判分逻辑与工具约束
- ✅ 域设计与判分链路的 6 项工程约束已固化，记录在 `docs/评测床设计.md` 第 4.1 节

**下一步就是把任务换成有区分度的（H1~H10），再跑消融。**

---

## 7. 已知局限（复述一遍，防止这份报告被过度解读）

1. 6 条任务、1 个域、1 个模型 → 结论**不可外推**
2. 用户是脚本化的 → agent 的「应对混乱」能力未被测试
3. NL 断言由 MiniMax 判定，本身有抖动（本轮 18×2=36 次判定，0 次异常）
4. **无外部分数对照** → 本报告只做**组内消融对比**，不宣称绝对水平
5. 任务由我们自己写 → 判分逻辑必须与 agent 实现**完全解耦**（v1 已做到：gold 由参考轨迹独立回放得出）
