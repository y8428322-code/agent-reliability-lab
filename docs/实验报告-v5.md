# 实验报告 v5：策略单一事实源 + 自动切分 vs 人工手写

- 日期：2026-11-01
- 模型：MiniMax-M3.1-Flash ｜ 框架：Qwen-Agent（上游 commit `31a4d36`，未魔改）
- 域：`telecom_cn`（10 客户 / 10 设备 / 5 库存 / 9 工具 / 17 任务）
- 数据：`results/ablation_v5.json`（**255 次运行**）｜ 分析：`scripts/analyze.py`
- 前置：v4 的数字**不再可比**（A/B 的策略来源从「手写 policy.md / 手写摘要」改为「同一份 yaml 自动渲染」）

---

## 1. 本轮要回答的问题

**「上下文工程」是一门手艺，还是一套可复用的方法？**

此前 `policy.md`（手写长文）与 `policy_digest.md`（手写结构化摘要）两份内容并不严格一致，
所以 v4 的 A→B 差距里混着「人工摘要多写了/漏写了什么」的偏置。
本轮把规范收敛到**单一事实源** `domain/policy_rules.yaml`，再由渲染器产出两种版式：

```
policy_rules.yaml  （唯一事实源：16 条规则，每条含 正文 body + 关键判据 criteria）
      ├── render_narrative()   → 长叙述版（规则埋在段落里、标题不出现、判据不单列）
      └── render_structured()  → 结构化版（红线前置 + 分节 + 判据要点化 + 按场景裁剪）
```

## 2. 变体与策略来源

## 4. 三个结论

### 4.1 上下文工程的效应**依然成立**，而且现在能干净归因

| 对比 | pass^3 变化 | 含义 |
|---|---|---|
| A（长叙述版）→ B（结构化版） | 0.765 → 0.882（**+0.117**） | 同源、只差呈现方式 → **+0.117 是「呈现方式」的净效应** |
| A → B_handwritten | 0.765 → 0.941（+0.176） | 同上，但摘要由人工撰写 |

并且 A 的**平均工具调用 11.33**（含 1 次失控），B 降到 6.12，手写版只有 3.45 ——
**长叙述版让 agent 反复查、反复改**；结构化后大幅收敛。

### 4.2 自动渲染版 ≈ 人工手写版（差**恰好 1 个任务**，且差异是行为随机性）

自动版 0.882 vs 手写版 0.941，差距 **0.059 = 1/17**，**全部来自 H10 一个任务**。

**读轨迹查机制**（B_context H10 trial=1）：

```
用户: 周涛，手机号 1320000999        ← 少一位
客服: 好的，我先为您核实身份信息。        ← 没有立刻调用工具（号码位数不对，先等确认）
用户: 啊说错了，是 13200009999
用户: 对，抱歉
客服: 没关系，我用更正后的号码为您查询。
客服调用工具 find_customer_by_phone({"phone": "13200009999"})   ✓ 查对了
客服: 身份已核实…接下来我为您查询账户和宽带状态。   ← 但对话已无回合去建单
```

对比手写版：第 2 轮**直接查**（拿到工具报错）→ 第 3 轮用正确号码重查 → 建单 → 3/3 通过。

**差异的性质**：不是「规则覆盖不同」——
两份版本**都没写**「查不到用户时应向用户确认手机号」这条规则（两版都靠工具错误信息里的引导语），
所以这不是自动切分丢信息，而是 **agent 面对可疑号码时「谨慎等确认」还是「先查后纠」的行为随机性**。

> **结论**：在本实验分辨率下，**自动渲染的结构化摘要可以替代人工手写**，
> 即「上下文工程」**可以是一套可复用的方法**——但证据强度仅等于 1 个任务的翻转，
> **不足以定论**，需要更多任务/更多 trial 复核。

### 4.3 减法机制与反思的结论**在本轮被推翻/修正**

| 变体 | v4（手写摘要） | v5（自动结构化） | 变化 |
|---|---|---|---|
| B_context | 0.941 | 0.882 | 基准下降 |
| D_guarded（+减法） | 0.882 | 0.882 | pass^3 0.882 → **0.824**（变差） |
| E（+双向反思） | 0.882 | 0.882 | pass^3 0.882 → 0.882（持平） |

D 在本轮**掉了稳定性**（T02 从 3/3 掉到 1/3，归因「未闭环」×3），
E 则把 NL 维度做到最高（0.993）但 pass^3 与 B 持平。

**与 v4 的差异说明什么**：v4 的 D/E 结论建立在「手写摘要」之上；
换成自动结构化版后，减法机制的效果**不再稳定**。
结合 4.1，**更稳的解释是：减法与反思的效果都依赖于策略文本的具体写法**，
而不是某个机制本身有普遍增益 —— 这与 v4 的结论方向一致，但把"机制有效"改成了"**效果脆弱**"。

## 5. 这轮的方法论收获

### 5.1 判分标准本身也要被审查

我事先定的「差距 ≤0.05」**从一开始就不可达**：
17 个任务的粒度意味着 **pass^3 的最小可分辨差异 = 1/17 = 0.059**。
任何小于这个值的比例阈值都没有统计意义。**定阈值时必须考虑实验的分辨率。**

### 5.2 "同源"是让对比有意义的前提

如果两份策略文本内容不一致，任何呈现方式的对比都会被内容差异污染。
把规范收敛到单一事实源 + 双渲染器，是让「呈现方式」成为一个**干净变量**的必要条件。

### 5.3 差异的归因不能停在数字上

0.059 的差距如果只看数字，会得出"人工更好"的结论；
读轨迹后发现是**一个任务上的行为随机性**，结论完全不同。

## 6. 局限

1. **1 模型 / 1 域 / 17 任务**，最小可分辨差异 0.059 → 本轮只能支撑"差 1 个任务"级别的结论
2. **H10 的机制判断基于 3 次 trial 的轨迹观察**，属于定性推断，未做统计检验
3. **NL 维度区分度弱**（0.922~0.993），有效判分仍靠 DB 维度
4. **用户脚本化** → 不测"应对混乱用户"
5. **无外部分数对照** → 只做组内消融
6. 两版策略**都没写**「查不到用户时应向用户确认」这类规则 —— 这本身是规则集的缺口，下一轮补
